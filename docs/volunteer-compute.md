# 志愿者算力池（设计方案）

状态：原型已实现（`docs/pool-prototype.md`）；2026-11-18 起可以接入训练器（学习器链接、`--pool-ingest`，默认关；按任务抽查，发现不一致只标记账号、不自动吊销；见 pool-prototype.md 第 11–13 节），还没有在 r8 上实际使用。目标是让感兴趣的玩家用自己的电脑加入采样，和现有的三台机器（Mac mini、14700KF、H 255）一起给训练提供数据。

## 1. 前提与范围

- **游戏文件由玩家自己提供。** 每个玩家都有自己的 Ballance 拷贝。客户端只读取玩家本机的安装目录，校验文件的 sha256，项目不分发任何游戏文件。要校验的文件：
  - 2002 年的 `physics_RT.dll`（sha256 `e72e4afc…`）；
  - `base.cmo`、`Database.tdb`、`3D Entities/`、`Text/`（x87-soft 引擎只读这四项；2002 引擎另要 `Bin/VxMath.dll` 和 `BuildingBlocks/physics_RT.dll`）。
- **志愿者只做采样，训练只在中心做。** 志愿者的电脑只跑无头游戏和策略前向：
  - Windows 跑 2002 headless，直接加载玩家本机的原版物理 DLL；
  - macOS / Linux 跑 x87-soft headless。
  - 不用显卡，也不开游戏窗口。
- **训练器留在局域网内，不直接暴露。** 训练器、模型检查点、内部机器都不对外开放。公网上只有一个网关。
- **不做的事：**
  - 在志愿者电脑上做梯度更新；
  - 收集玩家的游戏操作或纪录；
  - 读取安装目录以外的任何文件。

## 2. 总体结构

```
志愿者客户端 ──HTTPS/WebSocket──▶ 公网网关 ──▶ 验证器 ──▶ 汇集器 ──▶ 训练器（局域网，现有 RemoteHub）
   │                               │              │
   ├ 无头游戏（2002 / x87-soft）    ├ 令牌、限速    └ 抽样重放，逐位比对
   └ 策略前向（CPU）                └ 权重分发（按版本缓存）
```

- **网关**：放在 14700KF 上，通过现有的 Cloudflare tunnel 只开放 HTTPS 路径，例如 `ballrain.swung0x48.com/pool/`。不开 TCP 端口，也不经过局域网转发。
- **汇集器**：对训练器来说，它就是一个普通的远程主机。实现为网关进程里的学习器链接（`ballrain/pool/learner_link.py`，host 标签 `pool`）：它也从学习器拿实时的配置和参数来发任务。训练器这边的改动：池子数据的延迟修正和最大延迟（见第 5 节），一个默认关闭的开关 `--pool-ingest`，以及一个数据来源标签。
- **验证器**：可以和汇集器在同一台机器上，用本地的无头引擎重放抽查。

## 3. 协议（必须先改的地方）

现在的远程连接用 `multiprocessing.connection`（pickle 加 HMAC），只适合局域网。**pickle 反序列化不可信的数据，会在接收端执行任意代码**，所以对外之前必须替换：

- **控制消息用 JSON**，带 schema 和协议版本号。
- **数组用二进制帧**：固定 dtype、固定形状的扁平数组，`float16` 观测加 zstd 压缩，带长度和 sha256。两端都不执行任何来自对方的代码或 pickle。
- **主要接口：**

| 接口 | 方向 | 内容 |
|---|---|---|
| `POST /pool/hello` | 客户端 → | 令牌、客户端版本、引擎 sha、游戏文件 sha 列表、平台、愿意贡献的实例数 |
| `GET /pool/task` | ← 服务端 | 任务：run、策略版本、关卡、开局点 k、球序种子、任务类型（采样 / 评估 / 探索）、最长时长 |
| `GET /pool/weights/<版本 sha>` | ← 服务端 | 策略权重和观测统计。按版本 sha 命名、不可变，可以让 Cloudflare 缓存 |
| `POST /pool/chunk` | 客户端 → | 一段数据：任务 id、策略版本、按键序列、behaviour log-prob、奖励、每步观测的哈希链、压缩后的观测 |
| `POST /pool/heartbeat` | 客户端 → | 运行状态，用于限速和统计 |

- **开局和种子由服务端指定。** 客户端不能自己挑开局，也不能挑球序种子，所以也就挑不了“容易的局”。
- **带宽估算：**
  - 观测 208 维，用 `float16` 每步 416 B。PC 上每个 2002 实例约 210 步/秒，压缩后上传约 40 KB/s。
  - 权重约 3 MB，每 30–60 秒拉一次，平均约 50–100 KB/s。权重由 Cloudflare 缓存，网关几乎不额外承担流量。

## 4. 防投毒：确定性重放验证

物理是确定性的：同一个引擎、同一个开局、同一个球序种子、同一串按键，结果逐位相同。所以每段数据都能在服务端精确复现。

验证器用和客户端相同的引擎重放：Windows 客户端用 2002 headless，macOS / Linux 客户端用 x87-soft。两种引擎在第 1 关的训练观测上几乎逐位相同，只有 SR06 有 3 帧不同（docs/headless.md §13），但验证不依赖跨引擎一致。验证流程：

1. 客户端提交的数据里有：按键序列、每步观测的哈希链、奖励和 behaviour log-prob。
2. 验证器按“开局 + 种子 + 按键”在本地重放，比对**引擎状态**哈希链（引擎发来的原始字节，去掉带地址的字段），要求逐位一致；特征、log-prob、价值和奖励由验证器自己重算，在容差之内即可（2026-11-18 起的链 v3，`pool-prototype.md` §3.2、§10.6：志愿者可能用原生客户端或另一种 CPU，浮点舍入略有不同）。
3. **抽查比例（2026-11-18 起按任务）：**
   - 新账号的前 200 段（按步数算）的任务 100% 整段重放，通过前不进训练；
   - 之后每个任务以 15% 的概率整段重放（`[verify] task_sample`），每一段另做便宜的策略一致性检查，不通过就升级成整段重放；
   - 每天随机复查（还没做）。
4. **任何一次不一致（2026-11-18 起，用户的规则：坏数据自动拒收，吊销和回退由用户决定）：**
   - 这个任务的数据全部拒收 / 隔离，不进训练；账号标记为可疑（不吊销），之后它的每个任务都整段重放、验证通过后才进训练；
   - 已经进了训练的那部分，记下它覆盖的更新范围，写进 `runtime/pool/alerts/` 的提醒；吊销和是否回退由用户手动决定（pool-prototype.md 第 11.4 节）。
5. **统计层面再加一道：** 某个客户端的成功率、回报分布明显偏离同一开局区间的整体分布时，提高对它的抽查比例。

重放的开销：验证器每重放一步，花的时间和采样一步差不多。抽查 10% 时，验证器大约需要志愿者总算力的十分之一，由 14700KF 承担。

## 5. 数据过时问题

- **现状：** 局域网内的远程数据最多允许落后 2 次更新（`--max-stale-remote 2`），每次更新约 0.3 秒，也就是不到 1 秒。公网志愿者的延迟是秒到分钟级，按现在的规则数据会被大量丢弃。
- **方案（已实现，2026-11-18）：** 训练器对池子数据用 V-trace（截断重要性权重，当前价值网络重算目标），PPO 的裁剪以当前策略为中心；落后超过 `--pool-max-lag` 次更新（默认 300）的数据直接丢弃。原先设想的 N = 50 按 r8 的实测太小：r8 每次更新约 1.3 秒，发布间隔 + 任务时长 + 等验证合计约 100 次更新（pool-prototype.md 第 11.3 节）。局域网远程数据的处理不变。
- **上线前先在本地验证：** 用现有机器人为加入延迟，比较“落后 0 / 10 / 50 次更新”时的学习曲线。只有学习效果没有明显变差，才对外开放采样任务。
- **另一条路：** 评估任务和第 7 节的探索任务不受过时影响，最适合志愿者，可以先只开放这两类。

## 6. 客户端

- **形式：** 一个绿色包，含无头引擎、内嵌的 Python 运行环境、启动器，从 GitHub Releases 发布，源码公开、可以自己编译。
- **首次运行：**
  - 选择 Ballance 安装目录，校验文件哈希。不匹配时说明是哪个文件不一样，不会悄悄降级。
  - 输入令牌，可选填一个昵称，用于贡献榜。
- **对玩家电脑的约束：**
  - 低于正常优先级，默认实例数为核心数的一半，可以调整；
  - 检测到玩家在玩游戏（有 Player.exe 在运行）、使用电池、或 CPU 温度过高时自动暂停；
  - 保留停止开关文件（同 runner2 的 `--quiet-file`）；
  - 不需要管理员权限，不装服务，不开机自启，除非玩家自己勾选。
- **更新：** 启动时检查签名清单，用 ed25519 公钥校验后才下载新版本。版本过旧的客户端，服务端会拒绝它的数据。
- **杀毒软件：** 引擎会在内存里改原版物理 DLL 的一处比较函数，用于控制球序。这类行为可能触发杀毒软件的启发式报警，需要在说明里解释清楚，并提供代码签名。代码签名证书需要单独申请。

## 7. 任务类型与阶段

| 阶段 | 内容 | 参与范围 | 进入下一阶段的条件 |
|---|---|---|---|
| P0 本地准备 | 替换 pickle 协议、验证器、V-trace 和过时实验、客户端打包、网关 | 只在现有三台机器上 | 用现有机器模拟“陌生客户端”：注入伪造数据能 100% 被抓到；人为延迟下学习效果不变差 |
| P1 熟人内测 | 先跑评估任务，再跑采样任务；新客户端全量验证 | 3–5 位信任的玩家，手动发令牌 | 一周内没有验证失败；带宽、网关负载都在预算内 |
| P2 公开 | 自助申请令牌、抽样验证、信誉、网页贡献榜 | 所有感兴趣的玩家 | — |
| P3 探索任务（M4） | Go-Explore：从存档状态出发，随机或按策略探索，回报新到达的格子。任务彼此独立，不怕延迟 | 同 P2 | — |

建议在 M3 开始时启动 P0。第 1 关的 M2 阶段，三台机器约 7000 步/秒已经够用，瓶颈不在采样量上。

## 8. 隐私与公开展示

- 令牌和昵称只存在服务端。IP 只在限速时短期使用，不写日志，也不展示。
- **网页展示：**
  - “训练数据来自哪台机器”里加一行“社区”，显示社区贡献的总占比；
  - 贡献榜只显示玩家自己填的昵称和通过验证的步数。
- 客户端只上传第 3 节列出的内容，不上传任何本机信息（用户名、路径、硬件序列号）。游戏文件只上传哈希。
- 公开页面延续现有规则（见 tools/dashboard/README.md）：不出现路径、主机名、IP。

## 9. 训练端的容量

数据量翻倍后，现在的 Mac 训练器（每次更新约 0.3 秒）会先饱和。可以选：
- 把训练器挪到 14700KF 的显卡上，需要和显卡上的其他用途协调；
- 增大每次更新的 batch，降低更新频率，这也能缓解第 5 节的过时问题。

这一项在 P0 里一并做压测。

## 10. 已确认与待定（2026-11-17）

1. **引擎源码许可：已确认可以分发。** 编译好的无头引擎可以随客户端发布。
2. **令牌发放方式：用社区 Flarum 论坛的 OAuth 登录**（flarum-oauth-center 插件，授权码流程）。
   - 志愿者在 `https://ballrain.swung0x48.com/pool/login` 点登录，跳转到论坛授权（scope `user.read`），回调到 `https://ballrain.swung0x48.com/pool/oauth/callback`。
   - 网关在服务端用授权码换取论坛访问令牌，读取 `/api/user`，得到论坛用户 ID 和用户名，然后发放算力池令牌。
   - 论坛应用的 ID 和密钥只存在网关本机不进 git 的配置里；客户端只持有算力池令牌。
   - 论坛应用的配置：关闭隐式授权，开启强制状态验证和精确重定向 URI，论坛令牌有效期 600 秒（只在登录时读一次用户信息）。
   - 论坛：`https://forum.ballance.top/`。授权 `https://forum.ballance.top/oauth/authorize`，换令牌 `https://forum.ballance.top/oauth/token`，用户信息 `https://forum.ballance.top/api/user`。
   - 待定：是否限制可领令牌的账号（注册时长、用户组）以防小号。
3. **代码签名证书：暂不申请。** 内测阶段在说明里解释引擎为什么会触发杀毒软件报警；进入 P2 公开前再评估。
4. **训练器位置：** 社区规模上来后，训练器挪到 14700KF，使用本机的两块显卡（RTX 4070 SUPER、RTX 4070）。用显卡训练时，要先停掉本机占用显卡的其他程序，结束后恢复。在 P0 里做压测，确认它比现在 Mac 上的训练器快，再迁移。

## 11. 原型设计决定（2026-11-17，和用户逐项对过）

1. **任务类型：训练采样。** 原型把“领任务 → 用指定版本的策略从指定开局和种子采样 → 交回数据 → 验证”完整跑通；交回的数据先存盘，不进训练器。评估任务结构相同，一并支持。
2. **领令牌的门槛：** 论坛注册满 30 天、邮箱已验证、至少 5 条回复；每个论坛账号一个令牌；同时运行最多 8 个实例；令牌可随时吊销。只保存论坛用户 ID、用户名和昵称；邮箱读到即丢，IP 不写日志。
3. **主控程序：** 给玩家一个友好的界面（TUI 即可）。由主控程序负责登录、选择游戏目录并校验、设定实例数、启动和停止模拟器及其他 Python 组件、显示状态。分两个版本：
   - **Windows 版**：2002 headless，加载玩家本机的原版物理 DLL；
   - **全平台版**：x87-soft headless，Windows / macOS / Linux 都能跑。
4. **启停由玩家控制：** 原来的停止开关文件改成主控界面里的“开始 / 暂停”。**关闭主控程序时，必须同时关闭它启动的所有模拟器和组件**；主控程序崩溃或被强行结束时也一样。Windows 用 Job Object（KILL_ON_JOB_CLOSE），Linux 用父进程退出信号，macOS 由子进程监视父进程。
5. **网关和验证器** 放在 14700KF 上，以后可能调整。
6. **防作弊同第 4 节。** 令牌被吊销或数据被拒收时，服务端返回明确的原因码和说明，例如“第 N 段数据重放结果与提交不一致”。主控界面要把原因原样显示给玩家。
7. **贡献榜：** 显示论坛昵称，从论坛获取。主控界面提供“上榜”选项，**默认上榜**，玩家主动关闭才不显示。
