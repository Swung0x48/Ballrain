# 策略合并（蒸馏）

几个检查点各自擅长关卡的不同部分时，用蒸馏把它们合成一个模型：每个状态由负责那一段的老师给出动作分布，学生网络去拟合（KL(老师 ‖ 学生)）。工具在 `tools/merge/`。

## 什么时候用

PPO 训练里技能会此消彼长：r10 的石变飞跃和第三小节分数球从没在同一个检查点上同时好过，只能在不同的检查点里各自找到。合并能把它们拼回一个模型，再用它继续训练（配合 `train_m2 --anchor-mastered --anchor-teacher` 锚定这几段，否则训练会再把其中一项冲掉）。

## 步骤

1. **挑老师**：用冻结测试找出每一段最好的检查点（`tools/merge/collect.py --behaviour CKPT --until next-cp` 打印到达下一个盘点的生命数，以及离开每个小节时吃全球的生命数）。
2. **采集状态**：用老师组合在全关玩，每个小节由对应的老师行动（`--teacher 3=球.pt --teacher default=飞跃.pt`），交接点覆盖全关，并在关键段加权（`--ranges 936-25300:3,4000-5800,15500-16400`）。每个进程用一个空闲的无头副本标签（`--copy`），多开几个进程并行。训练如果对生命、分数、计时输入做随机化，采集也要照做（`--counter-rand` 用训练的同一份配置，`--counter-p` 是一条生命用随机化计数器的概率）：r10 第一次合并只用了真实计数器，冻结测试飞过石变 48/60，回到训练里却从 33–48% 掉到 17–33%。
3. **蒸馏**：`tools/merge/distill.py --label-by sector --teacher ... --init 飞跃.pt`。从一个老师的权重出发（它的观测归一化和价值网络一起保留），只训练动作网络；每个老师的状态权重相同；按生命留出 20% 做验证。
4. **纠偏（DAgger）**：让学生自己玩全关（`collect.py --behaviour 学生.pt`），在它实际到达的状态上仍由老师标注，把新数据加进去重新蒸馏（`--rounds r0 r1 ...`）。r10 做了两轮，第三小节留出生命上的 KL 从 0.66 降到 0.32。
5. **测试**：对合成模型逐段做冻结测试，和老师比较；然后用它 `--resume` 继续训练，先做几十次只训练价值网络的热身（`--value-warmup`），并锚定合并进来的几段。

## 容量测试

`distill.py --label-by prefix --fresh --hidden W,W`：一个全新的网络分别只学一个老师、同时学两个老师，再换不同宽度。同时学的拟合（训练集 KL、实际游戏里的成功率）如果和单独学差不多，就说明网络装得下，技能此消彼长是训练干扰，加宽网络不对症。

r10（2026-11-26）：256×256 的学生同时学飞跃老师（第 39,250 次）和分数球老师（第 44,562 次），训练集 KL 0.014 / 0.016（单独学 0.008 / 0.010），实际游戏飞过石变 58%、吃全第三小节的球 83%，和单独学的学生、512 宽的学生相当。

## r10 的合并结果

`models/L01-r10-m2`：第三小节由第 44,562 次标注、其余由第 39,250 次标注，约 210 万个状态，两轮纠偏。冻结测试（从 HS01 4740 TAS 交接）：飞过石变 36/60，吃全第三小节的球 33/40，第二小节的坑 21/30，第三小节护栏 27/30，第四小节通关 21/30。

## 注意

- 老师们的观测布局、动作数和帧率必须相同（工具会检查）。
- 检查点会被反序列化，只用自己训练出的检查点。
- 引擎来自 `--hl-bin` / `--hl-root` 或环境变量 `BALLRAIN_HL_BIN` / `BALLRAIN_HL_ROOT`；状态文件写在 `--out` 指定的位置，按惯例放在 `runtime/` 下。
