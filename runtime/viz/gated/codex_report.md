# r8 context-gated actor

**Decision:** split only the final actor layer by **ball type**, not sector. Wood at the sector-2 ramp and stone on the sector-4 south loop already need different heads. Three heads keep more training examples per head than crossing ball type with sector. No observation, action, critic, or rollout-format change.

**Routing:** `make_layout` begins with `valid`, then `ball_type[3]` at zero-based columns `1:4` (wood, paper, stone). On normalized input take the first maximum of those columns if positive; otherwise use wood. With the trainer’s RMS of binary features, a present bit is positive and absent bits are nonpositive; clipping preserves the sign. Unknown/all-zero ball types therefore have a deterministic fallback. Both Torch and NumPy use this rule.

**Growth:** the original `pi` output is head 0. Append independent paper and stone layers after the critic in parameter order; copy the legacy weight and bias and their complete Adam slots, including step and moments. Keep trunk, critic, RMS and all original slots. Each active head runs the same dense projection shape as before; select outputs per row, and leave unused heads out of autograd so Adam does not drift them. A gated resume restores the separate heads rather than cloning again. Legacy is the default for fresh runs and old checkpoints.

**Evidence:** CPU replay from the actual r8 u24315 checkpoint, without an engine: all logits and values exactly equal before/after splitting on 479 back-to-wood, 921 paper-start and 710 stone-start observations. The paper-start trace also changes to stone. The regression test includes the three recorded handovers, mixed random inputs, skewed/clipped RMS, unknown type, exact Adam copies, a stone-only PPO update with pre-existing momentum, disk resume, and remote parameter message → pool export → NumPy inference with deliberately different heads. This is evidence for migration and routing, not a measured improvement in gameplay.

**Enable / rollback (not executed):** keep a frozen pre-split r8 checkpoint. Prefer a separate run: copy that checkpoint to `<runtime>/m2-train/r8-gated/latest.pt`. In the existing r8 launcher keep all non-run flags (especially its current LR, feature/branch and curriculum settings); use **`--run r8-gated --resume --actor-heads ball_type`** instead of the old run/resume flags. Restart Python remote bridges on matching code before connecting. Subsequent `--resume` inherits the saved mode. To roll back, stop the experiment and use the original r8 launch settings with **`--run r8 --resume --actor-heads single`** against the preserved single-head checkpoint. Do not drop the extra tensors from a trained gated checkpoint: the shared trunk has also changed.

**Native volunteer path remains paused.** Before advertising support:

1. Extend `native/core/include/ballrain/policy.h` and `native/core/src/policy.cpp` to recognize `arch.kind = mlp_actor_critic_ball_type`, preserve the legacy kind, and validate/load four additional float32 arrays: `extra_heads.{0,1}.weight` `[n_act,last_hidden]` and `.bias` `[n_act]`. Preserve full sorted-array hashing and integrity checks.
2. At actor inference, route normalized columns `1:4` exactly as above. Run the original hidden layers once and use the legacy output, extra head 0, or extra head 1 respectively. Value, action sampling and log-softmax stay unchanged.
3. Add golden parity cases for all three heads, fallback, and a transformation. Only then advertise `actor_ball_type_v1` in `native/core/src/pool_client.cpp`. The Python gateway already requires this capability for gated tasks; it also distinguishes the new architecture in policy identity.

**Risks / next decision:** the shared trunk can still interfere; two routes with the same ball still share an output. Rare heads have fewer updates and retain older Adam history. Mixed-context batches cost up to three output projections and device synchronization for routing. Compare paired per-start success and attempt counts over the same windows as the baseline; watch paper performance and the wood→stone transition, not just overall success.

Both passed on rerun using a writable temporary Git store at the same merge base: **622 passed, 38 skipped across the two runs**. No game engine, native client, or deployment was used. The remote bridge also now waits for a fallback worker termination to finish before reusing its slot (Windows terminates asynchronously).
